## 3. Flujo de trabajo — cómo subir cambios sin romper

1. Leer este `CLAUDE.md` y el archivo objetivo completo antes de editar.
2. Aplicar el cambio (Edit para HTML / `i18n.js`).
3. Si tocaste **texto visible**: añadir o actualizar las keys `en` y `fr` correspondientes en `i18n.js`.

6. `git commit` con mensaje claro (`feat/fix/perf/docs/chore`) + `Co-Authored-By`.
7. `git push origin main`.
8. Esperar ~1-2 min el deploy de Vercel; verificar en `https://forodyt.vercel.app`.

**Verificación post-deploy útil:** `curl -s https://forodyt.vercel.app/<archivo>` para confirmar que el contenido nuevo está en línea antes de probar en navegador.

## 5. Sistema i18n (`i18n.js`)

- IIFE con diccionarios `D = { es:{}, en:{}, fr:{} }`.
- Atributos en el HTML: `data-i18n` (textContent), `data-i18n-html` (innerHTML), `data-i18n-attr` (atributos).
- ES **siempre** usa el texto del propio HTML: `applyI18n('es')` restaura los originales y **no** lee el bloque `es:` del diccionario (verificado en el código el 2026-09-24; la nota del 2026-08-22 que decía lo contrario era errónea). Las claves nuevas solo necesitan EN y FR.
- API global: `window.foroI18n.setLang(lang)` / `getLang()`.
- Detección de idioma: `?lang=` en la URL → `localStorage` `forodyt_lang` → default `es`.
- `setLang()` refleja el idioma en la URL (`?lang=en`) y sincroniza `canonical`, `og:url`, `og:locale`, `<html lang>`.

### Las 3 trampas de i18n (rompen el archivo entero)
1. Apóstrofo sin escapar en una cadena FR → `SyntaxError` → ningún idioma funciona.
2. Coma faltante tras una key → se rompe el parseo del bloque de idioma.
3. `data-i18n` en un elemento con hijos (ej. `<a>` con `<span>` dentro): el `textContent=` borra los hijos. Poner `data-i18n` en un span hoja.

**Prueba rápida tras tocar i18n.js:** en consola del navegador, `window.foroI18n` debe existir; si es `undefined`, el IIFE se rompió.

## 6. Trampas conocidas

- **Mojibake (codificación):** los archivos son UTF-8. PowerShell los lee como windows-1252 y corrompe acentos. Usar Edit o bash/perl con `:raw`.
- **CSS grid overflow en móvil:** `grid-template-columns: repeat(auto-fit, minmax(180px,1fr))` se resuelve a columnas fijas que desbordan el viewport. En media queries móviles usar `grid-template-columns: 1fr`.
- **Imágenes:** todas externas en `img/`. Sin herramienta WebP local (cwebp/ImageMagick/ffmpeg ausentes). Optimización vía PowerShell `System.Drawing`; el codificador PNG de .NET es pobre para logos planos → conservar el menor entre original y optimizado.
- **Lazy-load en pruebas:** las imágenes `loading="lazy"` cargan al hacer scroll; dar un par de segundos antes de capturar pantalla o se ven cajas vacías (falso negativo).
- **Chrome MCP:** `resize_window` no cambia el viewport real; para simular móvil (390px) usar la técnica de iframe.
- **Apps Script — pegar código sin que el editor lo reindente** (2026-09-17): el editor expone `window.monaco`. Se inyecta un `<input type=file>` en la página, se le suben los archivos del repo con la herramienta de carga del navegador, y se sustituye el modelo con `editor.executeEdits(...)`; se compara el SHA-256 del modelo contra el del archivo **antes de guardar** y otra vez tras recargar. Crear archivo: «+» junto a *Archivos* → Secuencia de comandos / HTML → escribir el nombre → Enter.
- **HtmlService y las imágenes:** `<?= dataUri ?>` dentro de `src` sale ROTO en el PDF (el escape contextual anula los `data:`). Usar `<?!= imgSrc_(dataUri) ?>`. **Nunca** escribir scriptlets (`<?`) dentro de un comentario HTML de una plantilla: también se evalúan.
- **Autorización de Apps Script:** la ventana emergente de permisos se abre fuera del grupo de pestañas de Claude; la acepta el director. Si el editor se queda en «Cargando…», *Detener* y volver a *Ejecutar*.
- **Enviar como `contacto@forodyt.com` desde Apps Script:** `GmailApp.sendEmail(..., {from})` solo funciona si la dirección está en *Gmail → Ver todos los ajustes → Cuentas → Enviar mensaje como* **y** el script tiene el permiso `https://mail.google.com/`. La **autorización granular de Google** (las casillas del diálogo de permisos) deja esa casilla **sin marcar** con facilidad, y entonces `GmailApp.getAliases()` lanza «Required permissions: https://mail.google.com/» y el envío cae al remitente de la cuenta sin avisar. Remedio: `_autorizarCorreo()` llama a `ScriptApp.requireScopes(ScriptApp.AuthMode.FULL, ['https://mail.google.com/'])` para volver a pedirlo y lista los alias que ve. El código nunca falla por esto: `enviarCorreo_()` usa `GmailApp` con `from` si el alias existe y `MailApp` si no.
- **El desplegable de funciones del editor no se «fija» con un clic al vuelo:** si se elige la función y se pulsa *Ejecutar* antes de que el desplegable se cierre, se ejecuta la anterior (aquí se corrió `abrirEnsayo` en lugar de `cerrarEnsayo`). Comprobar el nombre en el desplegable **y** en la primera línea del registro de ejecución.
- **Subir cambios al repo desde una sesión Cowork:** el proxy de git rechaza el push (repo fuera de las fuentes autorizadas de la sesión) y el conector de GitHub responde 403 al escribir. Se sube desde el navegador del director en `github.com/EmmanuelDelva/forodyt/upload/main/<carpeta>` (una carpeta por commit). **Antes de subir, `git fetch` y comparar con `origin/main`**: el 17-sep otra sesión fusionó los PR #17 y #18 a media tarea (Mesa V4 hasta las 11:12) y hubo que rebasar.
